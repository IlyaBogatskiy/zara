## [1.1.0] — 2026-06-29

### Added
- 💶 **Отслеживание цены во время распродаж**: каждый тик мониторинга, помимо наличия,
  считывает текущую цену товара (из того же JSON Zara — без второго запроса; Selenium-фоллбек
  парсит цену best-effort и не падает, если не нашёл). Цена хранится на товаре
  (`products.last_price_*`) и переживает рестарт. Карточка товара теперь показывает цену.
- 🔁 **Спросить «продолжать ли следить» после появления размера**: когда размер вернулся в
  наличие, бот больше не отписывается молча, а присылает кнопки **«✅ Да, следить за ценой и
  наличием» / «❌ Нет, остановить»**. «Да» переводит подписку в режим `WATCH_IN_STOCK`.
- 👀 **Режим наблюдения за товаром в наличии** (`subscriptions.mode` =
  `AWAIT_RESTOCK` / `WATCH_IN_STOCK`): в режиме `WATCH_IN_STOCK` бот уведомляет об изменении
  цены (вверх/вниз) и о том, что размер снова пропал; при пропадании симметрично спрашивает
  **«✅ Да, ждать появления» / «❌ Нет»**, возвращая подписку в `AWAIT_RESTOCK`.

### Changed
- Планировщик при появлении размера больше **не** делает авто-отписку — подписка ждёт
  решения пользователя (кнопки выше). Авто-отписка осталась только для режима «товар целиком».
- Живой эндпоинт операторского API `/api/availability` теперь возвращает наличие **и** цену
  (`ProductSnapshot`); путь карточек/мониторинга наполняет новые модели `ProductSnapshot` и `PriceInfo`.

## [1.0.1] — 2026-06-10

### Added
- 🐳 **Docker Compose**: весь стек одной командой (`docker compose up -d --build`) —
  PostgreSQL + `selenium/standalone-chrome` + бот. Образ бота тонкий (JRE, без Chrome):
  Selenium-фоллбек ходит в контейнер браузера через новый параметр
  `zara.driver.remote-url` (`RemoteWebDriver`); пустое значение — локальный ChromeDriver,
  как раньше. Все порты (операторский API, Grid, noVNC) привязаны к 127.0.0.1.
  Секреты — через `.env` (см. `.env.example`); дампы парсинга смонтированы в `./dumps`.

### Changed
- Все зависимости подняты до актуальных стабильных версий: Spring Boot 4.0.2 → **4.0.6**
  (Spring Framework 7.0.7, Hibernate 7.2.12, Jackson 3.1.2), java-telegram-bot-api 9.3.0 → **10.0.0**,
  springdoc 3.0.0 → **3.0.3**, Selenium → **4.44.0** (через переопределение `selenium.version` Boot BOM).
  Spring Boot 4.1 пропущен сознательно — пока только RC.
- Версии библиотек вынесены в раздел `<properties>` pom.xml.
- **Пакеты реорганизованы по слоям** вместо технических паттернов: `telegram/` (UI-слой:
  листенер + сессии + executor), `client/` (всё, что общается с Zara: клиенты, WebDriverFactory,
  PageDumper, исключение и модель скрейпа), `notify/` (UserNotifier + AdminNotifier), плоский
  `cache/`. Удалены пакеты `enums/`, `factory/`, `exception/`, `listener/`, `service/dto/`.
- Переименования: `ProductDetailsDTO` → **`ProductCard`**, `SizeDetailsDTO` → **`SizeInfo`**
  (модель результата скрейпа), `ProductDetailsUtil` → `ProductLinks` + `Sizes`.
- Сборка уведомлений мониторинга вынесена в **`UserNotifier`** — планировщик больше не знает
  ни про Telegram, ни про callback-константы UI.

### Removed
- Мёртвый код: `ChatRegistry` (write-only), `SizeAvailability` (использовалась одна константа),
  `formatAllSizes`, `fromSize`, неиспользуемые поля DTO.

## [1.0.0] — 2026-06-10

Первый стабильный релиз. Полная переработка прототипа: новая архитектура, нормализованная БД, быстрый HTTP-путь мониторинга, самодиагностика и тесты.

### Added
- **Быстрый путь мониторинга и карточек** через внутренний JSON-эндпоинт Zara (`products-details`): ~0.5 с вместо 10–30 с headless Chrome; ретрай при сетевых сбоях; выключатель `zara.api.enabled`.
- **Канарейка селекторов** (`SelectorCanary`): каждые 6 ч сверяет Selenium-парсинг с JSON API на живом товаре; расхождение или падение → алерт оператору.
- **Алерты оператору** (`AdminNotifier`) в Telegram (`zara.admin-chat-id`) с rate-limit 6 ч на тип проблемы.
- **Дампы страниц** (`PageDumper`): HTML + скриншот в `dumps/` при каждой поломке парсинга, с ротацией.
- **Кнопка «Отслеживать отсутствующие»**: когда товар появился целиком, но часть размеров ещё нет — мониторинг продолжается по подтверждению.
- **Операторский REST API + Swagger UI** (`/api/**`, `/swagger-ui.html`): ручной запуск тика и канарейки, проверка наличия, CRUD подписок, метрики кэша.
- **Причина изменения подписки** (`SubscriptionChangeReason`): `USER_ACTION` / `AUTO_AVAILABLE` фиксируется при каждой отписке; история подписок сохраняется (строки закрываются, не удаляются).
- **Восстановление после рестарта**: последнее известное состояние размеров персистится каждый тик (`last_known_in_stock`) и поднимается при старте — без потерянных и дублированных уведомлений.
- **Тесты**: жизненный цикл подписок на H2 (10 сценариев), логика переходов планировщика (11), Telegram-флоу (7), живой тест Zara API (4).
- Конфигурация через `ZaraProperties` (`zara.*`) и переменные окружения (`TELEGRAM_BOT_TOKEN`, `DB_*`, `ZARA_ADMIN_CHAT_ID`).
- README на четырёх языках (ru/en/me/sr), документация архитектуры в `docs/`.

### Changed
- **Архитектура переработана полностью** (см. `docs/CACHE_REDESIGN.md`): событийная шина (8 событий, 3 async-листенера) удалена; прямые синхронные вызовы; подписки пишутся в БД write-through.
- **Схема БД нормализована**: `products` (один на товар) + `subscriptions` (строка на чат×товар×размер, размер — сырая строка без enum-потерь); миграция с легаси-схемы автоматическая (`LegacyDataMigration`), старые таблицы остаются до ручного удаления.
- **Кэширование на Caffeine**: карточки товаров (`expireAfterWrite 6h`, коалесцирование конкурентных скрейпов), сессии диалогов (`expireAfterAccess 30m` — закрыта утечка).
- **Планировщик группирует проверки по товару**: один скрейп на товар за тик независимо от числа подписчиков; ошибки изолированы per-product; лог длительности тика.
- **Скрейпинг убран с потока Telegram-апдейтов** (`ScrapingExecutor`): бот отвечает всем пользователям, пока грузится чья-то карточка.
- Chrome работает без загрузки картинок; User-Agent и таймауты вынесены в конфиг.

### Fixed
- **Критический баг мониторинга**: проверка наличия читала атрибут `data-qa-action` с элемента `<li>` вместо кнопки размера — все размеры всегда считались отсутствующими, уведомления не приходили никогда.
- `return` вместо `continue` в цикле мониторинга — одна отсутствующая карточка обрывала весь проход.
- NPE на незнакомых ключах в кэшах (цепочки `get(chatId).get(...)` без проверок).
- Инвалидация одного чата стирала состояния мониторинга всех чатов.
- `findAllWithSizesByChatId` игнорировал параметр `chatId` и возвращал товары всех чатов.
- Поломка селекторов маскировалась под «всё распродано» — теперь это громкий `ZaraParsingException` с дампом страницы и алертом.

### Security
- Токен бота и креды БД переопределяются переменными окружения (дефолты в `application.yaml` — только для локальной разработки; токен следует ротировать).

## [0.1.0] — 2026-02

Прототип: Selenium-скрейпинг карточек, подписки на размеры через inline-кнопки, мониторинг по расписанию, три рукописных in-memory кэша с событийной синхронизацией, персистентность в PostgreSQL (`product_details` + `size_details`).
